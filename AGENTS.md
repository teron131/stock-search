## Data Architecture (Target State)

The application separates concerns into three distinct data files to decouple position sizing from market data and inference.

### 1. `portfolio.json` (Source of Truth)

Contains **only** the holdings configuration.

```json
[
  { "ticker": "NVDA", "quantity": 10, "delta": 1.0 },
  { "ticker": "AAPL", "quantity": 50, "delta": 1.0 }
]
```

### 2. `stats.json` (Market Data & Metadata)

Contains cacheable, non-inference data. Populated by `yfinance` or external market APIs.

- Price, Change, Market Cap, PE, RSI.
- Static metadata: Name, Sector/Bucket classification.
- **Cache Strategy**: This file is treated as a read-through cache. If a ticker is present and valid, it is used. If missing, the server performs a **live fetch** (see `StockIndicator`).

---

## API Hierarchy & Fallback Policy (Mandatory)

For fundamental statistics, always prefer free public web-source values with cache first, and keep `yfinance` as fallback.

1. Primary: direct web-source extraction from trusted public pages (for example `stockanalysis.com/stocks/{ticker}/statistics`).
2. Secondary: last successful local cache entry.
3. Final fallback: `yfinance` values.

Refresh expectations:

- Use a 1-day check/TTL for web-extracted fundamental stats before refreshing.
- Keep response behavior resilient: if refresh fails, use cached value; if no cache, use fallback source.

Rationale:

- Prioritize low-cost sources and consistency with public-facing website values.
- Reduce ticker-to-ticker inconsistencies from a single API source.

Known `yfinance` caveats (observed in this repo):

- Stock `PE` / `forward PE` may diverge from website-displayed values.
- Stock `revenueGrowth` and `earningsGrowth` from Yahoo `info` are often definition/period misaligned for TTM-style comparisons.
- ETF `forward PE` may be stale or inaccurate.
- ETF holdings can be incomplete and may not match issuer holdings pages.
- Values may not consistently match Yahoo website views across all tickers/endpoints.

Policy implication:

- Treat `yfinance` as a fallback for sensitive valuation/holdings fields, not the sole source of truth.
- For `revenue_growth` and `eps_growth`, prefer StockAnalysis period-aligned values.
- If Yahoo cannot produce a trustworthy period-aligned value, return `None` and let fallback resolution fill from higher-quality sources.

Forward P/E definition policy:

- `pe_forward` should use a fiscal-year-end weighted NTM EPS blend:
  - `eps_ntm = w * epsCurrentYear + (1 - w) * forwardEps`
  - `w = clamp(days_to_next_fiscal_year_end / 365, 0, 1)`
- Fallback order:
  1. NTM weighted blend (`PE_NTM_W`)
  2. FY1 definition (`price / forwardEps`)
- Rationale: different platforms mix FY0/FY1/NTM definitions; this keeps a smooth, calendar-aware transition from current-year to next-year EPS through the fiscal year.

### 3. `eval.json` (AI & Scoring)

Contains inference results, scores, and probabilities.

- Generated by LLM analysis or heuristic algorithms.
- Scores (Moat, Quality, Upside), Probabilities (Bull/Bear/Flat).

## Generation Pipeline (`generate_static_data.py`)

The generation script works in **reverse order** compared to a typical buy flow. It is primarily used for generating **Sample Data** for frontend development (`ui/sample_data/`) but can be used to backfill production data (`data/`).

1. **Fetch Stats**: Get market data for a candidate universe (Sample Tickers + Existing Portfolio Tickers).
2. **Generate Eval**: Compute scores and probabilities (simulated or real).
3. **Allocate**: Determine `quantity` for the portfolio based on the Stats and Eval data.
4. **Persist**: Write the three separate JSON files.

### Usage

- **Development (Default)**: `uv run python generate_static_data.py`
  - Writes to `ui/sample_data/` **only**.
  - Safe for testing without overwriting server data.
- **Production**: `uv run python generate_static_data.py --prod`
  - Writes to `ui/sample_data/` **AND** `data/`.
  - Use this to refresh the server's cache (`stats.json`).

## Server Logic (`dashboard.py`)

The dashboard implements a **live-first data loading strategy**:

1. **Load Portfolio**: Reads `data/portfolio.json` for the list of holdings.
2. **Load Cache**: Reads `data/stats.json` into memory.
3. **Hydrate Rows**:
   - **Live Fetch**: Always attempts to fetch real-time market data (Price, Changes, RSI, etc.) via `StockIndicator` (yfinance).
   - **Fallback**: If live fetch fails, uses the data from the `stats.json` cache.
   - **Static Data**: Uses `stats.json` for non-market fields like "Bucket" if not available otherwise.
4. **Merge**: Combines portfolio quantity with market data to calculate Notional Value and Weights.

This ensures the dashboard always shows the freshest data available, while remaining resilient to API failures.

## API Scope Boundaries

- `/api/portfolio` is web-app portfolio management and supports scope-based behavior (`priority`, `portfolio_live`, `all`).
- Scope/priority logic is portfolio-level only; do not reuse it for ticker-level APIs.
- Ticker APIs (`/api/portfolio/{ticker}` and `/api/stats/{ticker}`) are standalone and use `source=auto|live|cache`:
  - `auto`: live-first with cache fallback.
  - `live`: live-only; returns 502 if live fetch fails.
  - `cache`: cache-only ticker response.
- Keep ticker endpoints usable independently of portfolio scope for external API consumers.

## Configuration

See `.env` or `stock_search/config.py`.

- `OPENROUTER_API_KEY`: For LLM features.
- `NEWS_API_KEY`: For news fetching.
- `FAST_LLM`: Model identifier (defaults to `google/gemini-2.5-flash-lite-preview-09-2025`).
- `QUALITY_LLM`: Model identifier (defaults to `google/gemini-3-flash-preview`).

## Key Conventions

- **Imports**: `stdlib` > `third-party` > `local`.
- **Pathlib**: Use `Path` objects for all file I/O.
- **Errors**: Let exceptions bubble up unless implementing explicit fallbacks (e.g., news provider failover).
- **Async**: Use `ThreadPoolExecutor` for blocking I/O (yfinance), `async/await` for API handlers.
